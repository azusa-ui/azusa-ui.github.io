1. Core concepts: missing data mechanisms

All modern missing data methods rest on Rubin's taxonomy of missing data mechanisms[1]:

MechanismDefinitionExample (TB register)Implication
MCAR
Missing Completely At Random		Probability of missingness is unrelated to observed or unobserved dataLab result lost because a batch of forms was misplacedComplete-case analysis is unbiased but loses power
MAR
Missing At Random		Missingness depends only on observed dataOlder patients less likely to have HIV test recorded, and age is recordedLikelihood-based methods and multiple imputation are generally valid
MNAR
Missing Not At Random		Missingness depends on the unobserved value itselfPatients with worse outcomes are lost to follow-up because of the outcomeNo standard method fully corrects; sensitivity analysis needed
Caution

MAR vs MNAR is not testable from the observed data alone, because it depends on values you never see. Exploration and tests can support MCAR vs "not MCAR", but the MAR assumption underlying multiple imputation ultimately rests on substantive knowledge of how the data were collected, not on a statistical test[4],[5].

2. The practice dataset

All four scripts create the same dataset: the classic iris data (n = 150), with roughly 20% of values deleted completely at random from four variables using missForest::prodNA(). Sepal.Length is kept fully observed. Because the deletions are generated randomly by the software, the true mechanism here is MCAR by construction, which is a useful teaching device: we know the "correct" answer (the full iris data) and can judge each method against it.

library(mice)      # imputation workhorse
library(VIM)       # visualisation of missingness
library(tidyverse) # data manipulation

set.seed(123)                              # reproducibility of the random NA positions
dat <- iris %>%
  select(-Sepal.Length) %>%                # remove it first...
  missForest::prodNA(0.2) %>%              # ...so 20% NAs go into the other 4 variables
  mutate(Sepal.Length = iris$Sepal.Length) # ...then add it back complete

Syntax notes. set.seed() fixes the random number stream so everyone gets identical NAs. prodNA(0.2) replaces 20% of cells with NA at random positions. The select-then-mutate trick simply protects one variable from receiving NAs.

3. Step 1. Explore the missingness (script 1_explore_na_data.R)

Exploration answers three questions: how much is missing, where is it missing, and is there a pattern that hints at the mechanism.

3.1 How much is missing?

skimr::skim(dat)                  # full descriptive summary incl. n_missing per variable
naniar::prop_complete(dat)        # proportion of CELLS that are complete
naniar::prop_complete_case(dat)   # proportion of ROWS with no NA at all
naniar::miss_var_summary(dat)     # missing count and % per variable, sorted

     prop_complete prop_complete_case
         0.8400000          0.4266667

  variable     n_miss pct_miss
1 Petal.Length     38     25.3
2 Sepal.Width      33     22
3 Species          28     18.7
4 Petal.Width      21     14
5 Sepal.Length      0      0

Interpretation. 84% of individual cells are observed, but only 42.7% of rows are fully complete. This asymmetry is the central practical problem: even modest per-variable missingness (14 to 25%) destroys more than half the rows once you require complete cases. This is why deletion methods can be so wasteful in multivariable analysis.

3.2 Where is it missing? Pattern plots

md.pattern(dat, rotate.names = TRUE)   # mice: matrix of missingness patterns
aggr(dat, prop = FALSE, numbers = TRUE) # VIM: barplot + pattern combinations
matrixplot(dat)                         # VIM: whole-matrix view, better for large data

Figure 1. md.pattern(): each row is a missingness pattern (blue = observed, red = missing). Left margin = number of rows with that pattern; 64 rows are fully complete; right margin = number of missing variables in the pattern; bottom = missing count per variable.

Figure 2. VIM::aggr(): left panel shows missing counts per variable, right panel the frequency of each observed pattern combination.

3.3 Does missingness relate to other variables?

The script inspects whether the distribution of an observed variable differs between rows where another variable is missing versus observed. Under MCAR the distributions should look similar (apart from sampling noise).

# Distribution of Sepal.Length when Sepal.Width is missing vs observed
# (workshop uses niceFunction::histNA_byVar; equivalent ggplot2 shown)
dat %>%
  mutate(miss_SW = if_else(is.na(Sepal.Width), "missing", "observed")) %>%
  ggplot(aes(Sepal.Length, fill = miss_SW)) +
  geom_histogram(position = "identity", alpha = .6, bins = 20) +
  facet_wrap(~miss_SW, ncol = 1)

Figure 3. The Sepal.Length distribution looks broadly similar whether Sepal.Width is missing or observed, consistent with (but not proving) MCAR.

# Correlation among the NA indicators themselves (1 = missing, 0 = observed)
x <- as.data.frame(abs(is.na(dat))) %>% select(-Sepal.Length)
cor(x)

# Correlation of NA indicators with the OBSERVED values of other variables
dat %>%
  mutate(Species = as.numeric(Species)) %>%
  cor(x, use = "pairwise.complete.obs") %>%
  round(2)

NA-indicator correlations (all near zero):
             Sepal.Width Petal.Length Petal.Width Species
Sepal.Width         1.00        -0.05        0.11    0.12
Petal.Length       -0.05         1.00        0.12   -0.04
Petal.Width         0.11         0.12        1.00   -0.09
Species             0.12        -0.04       -0.09    1.00

Interpretation. Correlations near zero suggest that being missing on one variable is not associated with being missing on another, nor with the observed values of other variables. In real epidemiological data, a sizeable correlation here (say, missingness of smoking status correlating with age) would be evidence against MCAR and would point to variables that should enter the imputation model.

3.4 Little's MCAR test

naniar::mcar_test(dat)

  statistic    df p.value missing.patterns
1      38.8    40   0.522               14

Interpretation. Little's test[2] compares observed means across missingness patterns; the null hypothesis is MCAR. Here p = 0.522, so there is no evidence against MCAR, which matches how the data were generated.

Caution

Three limitations are worth remembering. First, a non-significant result does not prove MCAR; the test may have low power, particularly with small samples or weak covariate-missingness associations. Second, a significant result tells you the data are not MCAR but cannot distinguish MAR from MNAR[2],[5]. Third, it is a global test of means only; it can miss departures in variances or covariances. Fourth, the test was derived for continuous, approximately multivariate normal data; applying it to a dataset containing a categorical variable (Species here) stretches its assumptions, so the result should be read loosely. Many methodologists therefore treat it as one supportive piece of evidence rather than a gatekeeper.

4. Step 2. Deletion methods (script 2_deletion_na_data.R)

# Listwise (complete-case) deletion: keep only rows with no NA
dat_nona <- drop_na(dat)

# Many base R functions return NA unless told to remove NAs
mean(dat$Sepal.Width)               # NA
mean(dat$Sepal.Width, na.rm = TRUE) # 3.064

# Regression functions silently do listwise deletion by default
linreg <- lm(Sepal.Width ~ ., data = dat)
summary(linreg)

     original_n complete_case_n
            150              64

mean_default   mean_na_rm
          NA     3.064103

(from summary(linreg))
Residual standard error: 0.2416 on 58 degrees of freedom
  (86 observations deleted due to missingness)
Multiple R-squared: 0.6852

Interpretation. Three lessons. First, drop_na() discarded 86 of 150 rows (57%), even though only 16% of cells are missing. Second, base functions like mean() propagate NA by design; na.rm = TRUE performs available-case deletion for that single calculation. Third, and most importantly for practice: lm() and glm() quietly fit the model to complete cases only. The message "(86 observations deleted due to missingness)" is easy to miss, and published analyses sometimes do not report it.

When is complete-case analysis acceptable?

Complete-case analysis is unbiased under MCAR, and in regression it can also be unbiased under some non-MCAR conditions, for example when missingness depends only on the covariates and not on the outcome[5],[9]. Its main penalty under MCAR is lost precision (wider confidence intervals), which you can see in Section 7. With very small amounts of missingness (commonly cited as below about 5%, though this is a rule of thumb rather than an evidence-based threshold) complete-case analysis is often considered a reasonable primary analysis[8]. It is therefore too strong to say deletion is always wrong; the concern is bias when missingness is related to the outcome, plus the efficiency loss seen here.

5. Step 3. Single imputation (script 3_single_impute.R)

5.1 Simple substitution: mean, median, mode

# Mean imputation
mean_sub <- dat %>%
  mutate(Sepal.Width = replace_na(Sepal.Width, mean(Sepal.Width, na.rm = TRUE)))

# Median imputation
med_sub <- dat %>%
  mutate(Petal.Length = replace_na(Petal.Length, median(Petal.Length, na.rm = TRUE)))

# Mode imputation for a categorical variable
table(dat$Species)          # virginica is the most frequent level
mode_sub <- dat %>%
  mutate(Species = replace_na(Species, "virginica"))

SD of Sepal.Width:
    observed mean_imputed  reg_imputed
   0.4403098    0.3885028    0.4172883

Species counts:  before: setosa 38, versicolor 40, virginica 44 (+28 NA)
                 after:  setosa 38, versicolor 40, virginica 72

Interpretation. The run demonstrates empirically why simple substitution is discouraged for inference. Mean imputation shrank the standard deviation of Sepal.Width from 0.440 to 0.389 (a spike of 33 identical values at the mean), which attenuates variances, distorts correlations, and produces confidence intervals that are too narrow[4],[5]. Mode imputation inflated the modal category (virginica: 44 to 72), changing the species distribution substantially. These methods may still have a place in purely predictive machine-learning pipelines, where the goal is prediction accuracy rather than valid standard errors, but for aetiological or inferential epidemiology they are generally considered inappropriate.

Note on the workshop script

Script 3 contains an apparent typo: it imputes Petal.Length with median(Sepal.Width) (the median of a different variable). I ran both versions; the corrected line (median(Petal.Length, na.rm = TRUE) = 4.30) is shown above. This is a good reminder to always summary() your data after imputation.

5.2 Model-based single imputation with mice

# "Dry run": m = 1, maxit = 0 fits nothing but shows the default setup
ini <- mice(dat, m = 1, maxit = 0)
ini$method            # pmm for numeric, polyreg for Species, "" for complete vars
ini$predictorMatrix   # which variables predict which (1 = used as predictor)

# Change the method for Sepal.Width to deterministic linear regression
meth <- ini$method
meth[1] <- "norm.predict"   # alternatives: "norm.nob" (stochastic), "cart", ...

regImp <- mice(dat, m = 1, method = meth, printFlag = FALSE, seed = 123)
dat_imputed <- complete(regImp)   # extract the single completed dataset

Syntax notes. The maxit = 0 dry run is the recommended way to inspect and customise the setup before actually imputing. Defaults: predictive mean matching (pmm) for numeric variables, logistic regression (logreg) for binary factors, polytomous regression (polyreg) for factors with more than two levels. norm.predict imputes the deterministic regression prediction; norm.nob adds random residual noise (stochastic regression imputation).

Interpretation. Regression-based imputation preserved the SD better than mean imputation (0.417 vs 0.389, true observed 0.440). However, any single imputation, even a good one, has a fundamental limitation: the analysis afterwards treats imputed values as if they were observed, so standard errors do not reflect the uncertainty about the missing values and tend to be too small[3],[4]. This motivates multiple imputation.

6. Step 4. Multiple imputation with mice (script 4_multiple_impute.R)

Multiple imputation (MI) creates m completed datasets, each with different plausible imputed values drawn from their predictive distribution, analyses each one, and pools the m sets of estimates with Rubin's rules, which combine within-imputation and between-imputation variance so the standard errors properly reflect missing data uncertainty[3],[4].

6.1 Impute

miImp <- mice(dat, m = 5, printFlag = FALSE, seed = 123)
complete(miImp, 1)   # extract 1st imputed dataset (for inspection only)

How large should m be? The old default m = 5 rests on early results showing high relative efficiency with few imputations. More recent guidance suggests larger m, commonly 20 to 100[6]; two popular rules are the White, Royston and Wood suggestion that m should be at least equal to the percentage of incomplete cases[5], and von Hippel's quadratic rule targeting replicable standard errors[7]. With 57% incomplete cases here, m of about 50 to 60 would be more defensible in a real analysis; m = 5 is kept for speed in a teaching context.

6.2 Check convergence

plot(miImp)                                   # trace plots: mean and SD per iteration
miImp2 <- mice.mids(miImp, maxit = 35)        # continue the SAME chains for more iterations
plot(miImp2)

Figure 4. Trace plots of the chain means and SDs for each imputed variable across iterations (one coloured line per imputation chain). Healthy convergence: lines intermingle freely with no trend. With only 5 iterations the plot is hard to judge, which is why the script extends to maxit = 35.

Figure 5. After 35 iterations the chains mix well and show no systematic drift, supporting convergence of the MICE algorithm.

Syntax notes. with(mids, model) fits the model separately in each of the m completed datasets, never on a single "stacked" dataset. pool() applies Rubin's rules: the pooled estimate is the mean of the m estimates; the pooled variance adds the average within-imputation variance and the between-imputation variance (inflated by 1 + 1/m). The fractional degrees of freedom (for example df = 17.1 for Petal.Width) are the Barnard-Rubin adjustment and are expected with MI.

Interpretation, with appropriate caution. Several observations are consistent with theory. The complete-case analysis, although approximately unbiased here (as expected under MCAR), produced visibly wider confidence intervals and lost statistical significance for Petal.Length (CI crosses zero), reflecting the loss of 86 observations. MI recovered CI widths close to the full-data model and retained all associations. Note, however, that MI point estimates are not uniformly closer to the truth for every coefficient (for example, the Species contrasts moved somewhat away), which is a fair reminder that in any single dataset MI reduces expected error but does not guarantee a better estimate term by term; its advantages are properly demonstrated over repeated simulations rather than one realisation. With m = 5 there is also non-trivial Monte Carlo variability; rerunning with a different seed would give slightly different pooled estimates.

8. Practical guidance and reporting for your dissertation

A defensible workflow for an epidemiological analysis, consistent with the guidance of Sterne et al. and White et al.[4],[5]:

  1. Quantify and report missingness per variable and per case (miss_var_summary, pattern plots), and compare characteristics of complete vs incomplete cases.
  2. Reason about the mechanism from how the data were collected; use Little's test and missingness-covariate associations as supporting evidence only.
  3. Choose the primary approach. Very small, plausibly random missingness: complete-case may suffice. Otherwise MI under MAR is the usual default. Include the analysis-model outcome and all analysis-model covariates in the imputation model, plus auxiliary variables that predict missingness or the missing values; the imputation model should be at least as rich as, and compatible (congenial) with, the analysis model; congeniality formally concerns compatibility between the imputation and analysis models, not richness alone[5],[10].
  4. Set m in line with the fraction of missing information (often 20 to 100), check convergence plots, and check imputed vs observed distributions (for example densityplot(miImp), stripplot(miImp)).
  5. Pool with Rubin's rules; never average the imputed datasets into one, and never analyse a single completed dataset.
  6. Sensitivity analysis. Compare complete-case and MI results; if MNAR is plausible, consider delta-adjustment or pattern-mixture sensitivity analyses[5],[10].
  7. Report transparently: software and version, number of imputations, imputation methods per variable, variables in the imputation model, convergence checks, and both complete-case and MI estimates. STROBE recommends stating how missing data were addressed[11].
Time series and spatial note

Since your interest is time series and spatial epidemiology: standard MICE assumes independent rows, so it does not automatically respect temporal autocorrelation or spatial structure. For time series, methods that use temporal neighbours (for example Kalman smoothing or seasonal interpolation in the imputeTS package) or MI with time-structured predictors (lags and leads as covariates) are often more appropriate; for clustered or spatial data, multilevel imputation (for example mice with 2l.pan-type methods, jomo, or micemd) helps preserve the hierarchical structure. This is an active methodological area and the best choice is context dependent.

9. Pitfalls and points of debate

Claim you may hearMore balanced view
"Always use multiple imputation."MI is not automatically superior. With tiny amounts of missingness, complete-case analysis can be adequate; when missingness depends only on covariates in a regression, complete-case can even be unbiased where a poorly specified MI model is not[8],[9]. A badly built imputation model (omitting the outcome, ignoring nonlinearities or interactions, uncongenial with the analysis model) can introduce bias rather than remove it[5],[10].
"Little's test told me the data are MCAR."The test can fail to reject for reasons of power, and can never validate MAR vs MNAR. Treat p > 0.05 as "no evidence against MCAR", not "MCAR confirmed".
"Mean imputation is fine because n is preserved."It preserves n but corrupts the variance and covariance structure; the demonstration in Section 5 (SD 0.440 to 0.389) shows the mechanism. For inference this generally biases standard errors downward. In predictive ML pipelines it is sometimes an acceptable, pragmatic choice.
"MI fixed my MNAR problem."Standard MI assumes MAR. Under MNAR it can reduce but not eliminate bias, and can occasionally worsen it; sensitivity analyses (delta adjustment) are the recommended response[5],[10].
"m = 5 is enough."Historically defended on relative-efficiency grounds; modern practice with cheap computing generally uses more, scaled to the fraction of missing information[6],[7].
"Impute, then pick one completed dataset."This is single imputation with extra steps and understates uncertainty. Always analyse all m datasets and pool.
